# Модуль Notifications

## Зона ответственности

Модуль создаёт внутренние уведомления и доставляет их по каналам: UI/SSE, email, чат. Бизнес-модули не должны
вызывать email/chat клиенты напрямую; они публикуют domain events.

## Текущее состояние

Есть только `NotificationService` с тремя методами. Таблицы, implementation, клиенты внешних систем, retry и API нет.

## Что нужно исправить

1. Текущий `NotificationService` смешивает создание notification и конкретные transport-каналы.
2. `String type` лучше заменить enum или стабильными кодами.
3. Если email отправлять внутри транзакции request, ошибка SMTP откатит бизнес-операцию. Обрабатывать события
   после commit.
4. Redis есть в dependencies, но его роль не определена. Его можно использовать для pub/sub SSE, но PostgreSQL должен оставаться
   источником истины для unread notifications.

## Схема внутренних уведомлений

```sql
CREATE TABLE notification (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id bigint NOT NULL REFERENCES users(id),
    request_id bigint REFERENCES request(id),
    type varchar(50) NOT NULL,
    title varchar(255) NOT NULL,
    body text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    read_at timestamptz
);

CREATE INDEX idx_notification_user_unread
    ON notification(user_id, created_at DESC)
    WHERE read_at IS NULL;
```

## События

```java
public record RequestStatusChangedEvent(
        Long requestId,
        String previousStatus,
        String newStatus,
        Long actorId
) {
}
```

```java
@Component
class RequestNotificationListener {

    @Async
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void onStatusChanged(RequestStatusChangedEvent event) {
        notificationFacade.notifyStatusChanged(event);
    }
}
```

Для надёжной доставки лучше outbox pattern. `@Async` без outbox может потерять событие при аварийном завершении.

## План работ

1. Определить типы событий и получателей.
2. Добавить notification migration/entity/repository.
3. Разделить `NotificationWriter`, `EmailSender`, `ChatSender`, `SsePublisher`.
4. Создать listeners для request/workflow events.
5. Включить async execution через `@EnableAsync` и настроенный `TaskExecutor` с ограниченной очередью.
6. Добавить API списка, unread count и mark-as-read.
7. Добавить SSE как оптимизацию, но не как единственное хранилище.
8. Для email/chat добавить timeout, retry с backoff и метрики.

## Тесты

- событие при rollback не создаёт notification;
- получатели рассчитываются по role/department/assignment;
- пользователь не может читать и отмечать чужие notifications;
- mark-as-read идемпотентен;
- ошибка email не откатывает workflow;
- unread count совпадает с фактическим списком.

## Детальная декомпозиция задач

### NTF-01. Составить матрицу событие → получатель → канал

Пример решения:

| Событие | Получатели | UI | Email | Chat |
| --- | --- | --- | --- | --- |
| Request created | Heads department | yes | optional | no |
| Head approved/rejected | Author | yes | yes | no |
| Assigned | Executor, author | yes | yes | optional |
| Started | Author | yes | no | no |
| Completed | Author, department | yes | yes | optional |

Команда заполняет все строки и определяет, нужны ли preferences. Без матрицы не писать listeners.

### NTF-02. Создать storage

1. Migration `notification` с FK/indexes.
2. Добавить unique deduplication key, например `(event_id, user_id, type)`, если event может быть доставлен повторно.
3. Entity с user/request ManyToOne LAZY, enum/string type, title/body, created/read.
4. `createdAt` generated safely, readAt nullable.
5. Repository queries always scoped by user ID.
6. Не включать body в `equals/hashCode/toString`.

Приёмка: unread partial index используется; duplicate event не даёт duplicate notification.

### NTF-03. Определить domain events

Каждое event:

- immutable record;
- event ID UUID для deduplication;
- request ID, actor ID, before/after values;
- occurredAt из injected Clock;
- никаких JPA entities и lazy proxies;
- никакого pre-rendered locale-specific body, если планируется i18n.

Для MVP можно title/body на русском, но шаблоны централизовать в renderer, а не listeners.

### NTF-04. Вычислять recipients

Создать `NotificationRecipientResolver`. Он принимает event/type и возвращает set user IDs.

Правила:

- удалять duplicates;
- не уведомлять actor, если того не требует матрица;
- не уведомлять disabled users;
- department recipients искать repository query, не загружать всех users;
- missing optional executor/approver не exception.

Тест на каждую строку матрицы.

### NTF-05. Transactional listener и persistence

1. Listener AFTER_COMMIT, async only после настройки executor.
2. В async method открыть новую transaction для notification rows.
3. Ошибку listener логировать с event ID; не терять в silent future.
4. Для MVP retry через Spring Retry/scheduler может быть позже, но документировать возможную потерю.
5. Для надёжной версии — outbox row в business transaction, worker обрабатывает.

### NTF-06. Read API

1. GET notifications — current user only, page, `unreadOnly`, sort createdAt desc.
2. GET unread-count — count query, не load list.
3. PUT read — update where id AND user_id; foreign ID → `404`.
4. PUT read-all — bulk update current user's unread rows.
5. Mark read idempotent: не менять first readAt при повторе.
6. DTO не содержит UserEntity/RequestEntity.

### NTF-07. SSE

1. Определить timeout/heartbeat/reconnect protocol.
2. Связать emitter с current user; чужой user ID не принимать.
3. Удалять emitter при complete/error/timeout.
4. На reconnect frontend сначала читает REST unread/list; SSE не гарантирует history.
5. Для нескольких app instances нужен Redis pub/sub или broker; один in-memory registry работает только на одном instance.

### NTF-08. Email/chat adapters

Каждый канал имеет interface и adapter. Бизнес-сервис не знает SMTP/Telegram URL.

Нужно:

- внешние credentials только в env/secrets;
- connect/read timeout;
- retry only transient errors, не bad address/template;
- ограничение attempts и dead-letter state;
- не логировать полный sensitive body/credentials;
- fake adapter для tests/local.

### NTF-09. Приёмочные тесты

- rollback → no notification;
- commit → exact recipient rows;
- duplicate event → no duplicate;
- foreign read denied;
- unread count/read-all/idempotency;
- SSE connect/disconnect/reconnect;
- external channel failure does not change request status;
- async executor saturation has defined behavior/metric.
