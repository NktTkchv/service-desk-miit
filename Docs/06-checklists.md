# Модуль Checklists

## Статус модуля

Пакет `ru.miit.servicedesk.checklists` и таблицы чек-листов сейчас отсутствуют. README при этом относит чек-листы
к будущей функциональности. Этот гайд описывает создание модуля с нуля.

## Модель

Нужно разделить:

- шаблон чек-листа для услуги;
- пункты шаблона;
- снимок чек-листа, созданный для конкретной заявки;
- отметку о выполнении, кто и когда её поставил.

Нельзя читать шаблон на лету для старой заявки: администратор может изменить шаблон, но старая заявка
должна сохранить свой исходный набор пунктов.

## Предлагаемая схема

```sql
CREATE TABLE checklist_template_item (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    service_id bigint NOT NULL REFERENCES service_catalog(id),
    title varchar(255) NOT NULL,
    position integer NOT NULL,
    required boolean NOT NULL DEFAULT true,
    active boolean NOT NULL DEFAULT true,
    UNIQUE (service_id, position)
);

CREATE TABLE request_checklist_item (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    request_id bigint NOT NULL REFERENCES request(id),
    template_item_id bigint REFERENCES checklist_template_item(id),
    title varchar(255) NOT NULL,
    position integer NOT NULL,
    required boolean NOT NULL,
    completed boolean NOT NULL DEFAULT false,
    completed_by bigint REFERENCES users(id),
    completed_at timestamptz,
    UNIQUE (request_id, position),
    CHECK ((completed = false AND completed_at IS NULL)
        OR (completed = true AND completed_at IS NOT NULL))
);
```

## План работ

1. Создать V-миграцию, entities и repositories.
2. Добавить admin CRUD для template items.
3. При создании заявки копировать active template items в `request_checklist_item`.
4. Разрешить executor отмечать и снимать отметку.
5. Запретить workflow-переход в `DONE`, пока есть невыполненный required item.
6. Публиковать event при полном выполнении, если он нужен UI/notifications.

## Пример отметки

```java
@Transactional
@PreAuthorize("hasRole('DUTY_OFFICER')")
public ChecklistItemDto setCompleted(Long itemId, boolean completed) {
    RequestChecklistItemEntity item = itemRepository.findDetailedById(itemId)
            .orElseThrow(() -> new EntityNotFoundException("Checklist item not found"));
    if (!item.getRequest().getExecutor().getId().equals(currentUser.id())) {
        throw new AccessDeniedException("Only assigned executor can update checklist");
    }

    item.setCompleted(completed);
    item.setCompletedBy(completed ? userRepository.getReferenceById(currentUser.id()) : null);
    item.setCompletedAt(completed ? clock.instant().atOffset(ZoneOffset.UTC) : null);
    return ChecklistMapper.toDto(item);
}
```

`Clock` лучше инжектить, чтобы тесты времени были детерминированы.

## Тесты

- снимок не меняется после редактирования template;
- позиции внутри template/request уникальны;
- только назначенный executor меняет item;
- `completedBy`/`completedAt` заполняются и очищаются согласованно;
- optional item не блокирует `DONE`, required item блокирует.

## Детальная декомпозиция задач

### CHK-01. Уточнить domain-правила

До migration комана отвечает:

1. У каждой услуги один шаблон или несколько версий?
2. Можно ли менять/удалять template item, если есть requests?
3. Кто отмечает item: только executor или staff/admin?
4. Можно ли снять отметку после DONE?
5. Нужен ли comment/evidence/file на item?
6. Когда создаётся snapshot: при request create или assignment?

Рекомендуемый MVP: один active template на service, snapshot при create, отмечает только executor, после DONE не меняется.

### CHK-02. Создать migration и entities

Шаги:

1. Создать migration по схеме выше.
2. Проверить indexes: template by service/active/position; request items by request/position; optionally incomplete required.
3. Создать `ChecklistTemplateItemEntity`, `RequestChecklistItemEntity`.
4. Связи: template → service ManyToOne; request item → request/template/completedBy ManyToOne.
5. `template_item_id` nullable, чтобы snapshot остался валидным после deactivate/template cleanup.
6. Не каскадить delete request/user/service без domain-решения.
7. Добавить Bean Validation и DB checks для position/title/completion pair.

Приёмка: Hibernate validate, clean migration, duplicate position rejected, completion timestamp constraint works.

### CHK-03. Template admin CRUD

Создать DTO/repository/service/controller.

Операции:

- list ordered by position;
- add item;
- update title/required/position;
- deactivate item;
- reorder several items atomically.

Для reorder не менять positions по одной с промежуточным unique conflict. Варианты: deferred constraint, temporary negative positions в transaction или delete/reinsert с аудитом.
Для MVP можно не делать bulk reorder, а задавать position при create/update и ловить conflict.

Доступ: read authenticated, mutations ADMIN, CSRF.

### CHK-04. Создавать snapshot

Алгоритм:

1. Получить active template items service, order by position.
2. Для каждого скопировать title, position, required в request item.
3. Сохранить batch, не N отдельных flush.
4. Обеспечить idempotency: unique request/position; повторный вызов не дублирует.
5. Вызывать в transaction request creation.

Обсудить: если в request нет items, это валидный empty checklist, а не ошибка.

### CHK-05. Чтение и изменение request checklist

1. GET проверяет request visibility через Requests authorization service.
2. PUT item completed загружает item вместе с request/executor.
3. Проверяет actor == executor и request в ASSIGNED/IN_PROGRESS (решить, разрешать ли ASSIGNED).
4. При true устанавливает actor/time; при false очищает оба.
5. Повторная та же команда идемпотентна или обновляет timestamp? Рекомендация: не обновлять.

### CHK-06. Интеграция с complete

Метод `areRequiredItemsComplete(requestId)` должен делать efficient `NOT EXISTS`/count query, а не загружать коллекцию.

Правило:

- no required items → true;
- any required incomplete → false;
- optional incomplete не влияет;
- inactive template item не влияет на уже созданный snapshot.

Workflow complete вызывает эту проверку в той же transaction.

### CHK-07. Приёмочные тесты

- migration constraints/indexes;
- snapshot copies values and is immutable from template changes;
- duplicate snapshot does not duplicate;
- access matrix viewer/executor/admin/foreign user;
- complete/uncomplete timestamps;
- race two updates item: last-write semantics или version — решить;
- workflow completion with required/optional/empty checklist;
- controller validation и CSRF.
